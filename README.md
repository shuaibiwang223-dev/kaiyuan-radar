# 开源雷达 · GitHub 涨星观察

一个全中文的网站，**每 3 小时自动更新一次**，看哪些 GitHub 开源项目正在变热。手机、电脑都能直接打开，不用登录。

由 Codex 做的 starwatch 改造而来：保留了中文界面和分类，把“靠 Codex 定时触发”换成了 GitHub 免费的定时任务，**不用开电脑，也不消耗任何 AI 额度**。

## 能看什么

| 菜单 | 内容 |
|---|---|
| 发现项目 | 所有监测中的项目，可按 24 小时 / 7 天 / 30 天涨星、总星数排序，按分类筛选，可搜索 |
| 热门榜 | GitHub 官方的今日 / 本周 / 本月热门榜 |
| 涨星变化 | 每次更新时星数有变化的项目，可以只看“突然上涨”或“掉星” |
| 我的收藏 | 点 ☆ 收藏的项目（只存在当前设备上） |
| 使用说明 | 数据怎么来、最近的自动更新记录、有没有出错 |

点项目名可以看详情：星数走势图、许可证、创建时间等。

## 第一次部署（只需做一次）

1. 在 GitHub 新建一个**公开**仓库（例如 `kaiyuan-radar`），把这个文件夹里的所有文件上传进去。
2. 打开仓库的 **Settings → Pages**，在 **Source** 里选 **GitHub Actions**。
3. 打开仓库的 **Actions** 页面，点左边的“每 3 小时更新数据”，再点右边的 **Run workflow**，手动跑第一次。
4. 大约 3～5 分钟后，网址会出现在 Settings → Pages 页面顶部，格式是 `https://你的用户名.github.io/kaiyuan-radar/`。之后每 3 小时自动更新。

> 刚开始的 24 小时里，涨星数会显示“积累中”。这是正常的：要有两个时间点的数据才能相减。

## 常见调整

- **改更新频率**：编辑 `.github/workflows/update.yml` 里的 `cron: '17 */3 * * *'`。`*/3` 就是每 3 小时，改成 `*/6` 就是每 6 小时。
- **改关注的领域**：编辑 `collector/model.mjs` 里的 `TOPIC_QUERIES` 列表，比如加上 `'topic:pneumatic'`。
- **加中文释义**：编辑 `web/zh.js`，按 `'作者/项目名':'中文说明',` 的格式添加。
- **监测池上限**：`collector/model.mjs` 里的 `POOL_LIMIT`，默认 3000 个。

## 数据边界（实话实说）

- 不是 GitHub 全站，而是按你关心的领域 + 新项目 + 官方热门榜，持续扩充的监测池。
- 涨星数是两个时间点的**总星数之差**（净变化）。有人取消收藏也会算进去，所以可能是负数。
- GitHub 的定时任务在高峰期可能晚几分钟到半小时才运行。
- 数据只保留最近 95 天；整个仓库里只存最新一份数据（放在 `data` 分支），不会越存越大。

## 文件说明

```
collector/model.mjs   分类、涨星计算、搜索条件
collector/collect.mjs 采集程序（GitHub Actions 每 3 小时运行一次）
web/                  网页（index.html、app.js、style.css、zh.js 中文释义）
scripts/build-site.mjs 把网页和数据合成网站
.github/workflows/update.yml 定时任务配置
tests/                自动测试，运行 npm test
```
