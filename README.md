# 开源雷达 · GitHub 涨星观察

全中文的 GitHub 涨星排行网站：**全站所有 1000 星以上的项目（约 6.6 万个）全部监测**，再加上涨得快的新星小项目。手机、电脑都能直接打开，不用登录。

网址：https://shuaibiwang223-dev.github.io/kaiyuan-radar/

## 监测范围和更新频率

| 范围 | 数量 | 刷新频率 |
|---|---|---|
| 全站 1000 星以上 | 约 6.6 万个，一个不漏 | 每 3 小时全部刷新 |
| 新星池：1000 星以下、最近新建或涨得快的项目 | 最多 1.5 万个 | **每小时刷新** |
| 全站项目里一天涨 100 星以上的 | 不固定 | **每小时刷新** |
| GitHub 官方热门榜 | 今日 / 本周 / 本月 | 每 6 小时 |

由 GitHub 免费的定时任务完成，不用开电脑，也不消耗 AI 额度。

## 能看什么

| 菜单 | 内容 |
|---|---|
| 涨星排行 | 按 24 小时 / 7 天 / 30 天 / 近半年涨星、总星数排行，可按分类筛选 |
| 🚀 急剧上涨 | 还没大火（5000 星以下或 90 天内新建）、正在猛涨的项目 |
| 热门榜 | 今日、本周、本月（GitHub 官方）+ 近半年（自己算） |
| 涨星变化 | 每次更新时星数明显变化的项目 |
| 我的收藏 | 点 ☆ 收藏的项目（只存在当前设备上） |
| 搜索 | 顶部搜索框，搜全部监测项目 |

## 数字怎么算

- “24 小时涨星”= 现在总星数 − 24 小时前总星数，其他区间同理。是净变化，可能为负。
- 历史不够时：如果项目是区间内新建的，涨星 = 全部星数；否则显示“积累中”，不编造。
- “近半年”“30 天”需要时间积累，刚上线时主要是新建项目有数字，会越来越全。

## 常见调整

- **监测门槛**：`collector/model.mjs` 里的 `CORE_MIN_STARS`（默认 1000）。改成 500 约 12.6 万个项目，全站扫描会变慢。
- **新星池大小**：`RISING_LIMIT`（默认 15000）。
- **新星发现条件**：`risingQueries` 函数。
- **中文释义**：编辑 `web/zh.js`。
- **立即全站扫描**：仓库 Actions 页面 → “每小时更新数据” → Run workflow → 勾选“立即做一次全站扫描”。

## 数据存放

采集数据存在仓库的 Release「data-store」里（state.json.gz，另有上一份备份 state-prev.json.gz）。**不要删除这个 Release**，否则历史数据会丢失。

## 文件说明

```
collector/model.mjs    分类、历史存储、涨星计算、搜索分区
collector/collect.mjs  采集程序（每小时运行，每 3 小时全站扫描）
scripts/build-site.mjs 把数据拆成排行榜、搜索索引、详情、走势小文件，生成网站
web/                   网页（index.html、app.js、style.css、zh.js）
.github/workflows/update.yml  定时任务
tests/                 自动测试：npm test
```
